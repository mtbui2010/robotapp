# Record raw VLA episodes

A panel under the teleop strip (Cameras tab), drawn only when the robot has a recorder AND the `⏺` button next to the tabs is on (hidden by default; always shown while a recording runs) (`GET /recorder`, `RECORDER` config; 404 = nothing shown).

1. Fill the **fields** (the robot's config names them; kcare: `action`, `target object`, `target location`, `destination object`, `destination location`). Only `action` is required. There are **two rows** of fields (e.g. `open drawer` in one, `close drawer` in the other: no retyping); the **checkbox** of a row says which one **● Record** uses (one is always checked). Before each row a **Go to…** drop-down (the same saved Go to poses as the teleop strip) picks the pose that row **starts from**: pressing Record first sends the arm there (the button reads `going to <pose>…`; slowly, at the poses' speed), and only when it has arrived does remote control and the recording begin, so by default the move is NOT in the episode. Tick **rec first** (shown once a pose is chosen) to start the recording BEFORE the move: the move is then part of the episode (the backend marks it as its init part) and remote control starts again when the arm arrived. Empty = record from where the arm is. If the move fails before a recording nothing is recorded; with rec first the recording is already running, remote control stays off and the message says to stop or discard it. The **checkbox** that picks the row is the first thing of each row. The rows are kept in the browser.
2. The **✨ Generate** button (sparkles icon) makes a sentence from them: a **random template** that uses every filled field, with synonyms (`pick` -> `grab`, `top` -> `first`), so the same episode gets a new
   wording each time; pressing Generate again gives a DIFFERENT sentence than the one shown (when the fields allow another). There is no prompt box any more: ✨ of a row only SHOWS a sample sentence under that row (a demo of the wording; press again for another). Pressing **● Record** always makes a new sentence from the checked row, so the next
   episode is worded again.
   Open / close a drawer (action `open` or `close`, object `drawer`, optional location `top`/`middle`/`bottom`) has its own templates and the synonyms `open` -> `pull open`, `close` -> `shut`: 8 sentences without a location, ~24 with one (2026-11-18).
   `align` (shoes; with `destination_location` `entrance` -> `align the shoes and put them at the entrance`) and `wipe` (spill / table; with `destination_object` `towel` -> `wipe the spill with the towel`) have their own templates and verb synonyms too (2026-11-18).
3. **● Record** starts remote control (the teleop function the config names) and the recording together. While recording: the prompt, a clock, the camera frame counts.
4. **✔ Success** / **✘ Failure** stop remote control and save the episode with that label (failures are kept, labelled); **🗑 Discard** throws it away. The copy to the shared folder runs **in the background** (a `⏳ saving…` line shows while it runs): ● Record is available again at once. No confirmation is asked (see [teleop](teleop.md)).

Record is disabled, with the reason as its tooltip, when the recorder is not running on the robot, a run is in flight, or the shared folder cannot be written. The field
values are remembered in this browser only (localStorage).

Backend: `GET /recorder`, `POST /recorder/prompt {fields}`, `POST /recorder/start {prompt, meta}`, `POST /recorder/stop {label}` (robot_agent `api/recorder.py`);
the recorder itself is `robot_teleop.recorder` on the robot, writing `<data_dir>/raw/<date>/ep_NNNN/` (`data_dir` = `../vla_data`, relative to the repo root: the `vla_data` folder next to the repos) (raw: nothing resampled or trimmed). Helpers:
`frontend/lib/recorder.ts`, hook `useRecorder.ts`, component `RecorderBar.tsx`.
